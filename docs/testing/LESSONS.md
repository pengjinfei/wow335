# 从阿努巴拉克那一轮攻坚里带走的东西（2026-09-13 ～ 09-15）

这份文档给**下一个 boss** 用。阿努巴拉克的逐轮细节在 [boss 记录](bosses/heroic-an-anubarak/README.md)，
这里只留可迁移的：通用方法、引擎层已修/未修的系统性缺陷、口径陷阱清单、以及待办。

结果口径：阿努巴拉克从 40%（24/60 场）提到 **80%（8/10 场，Fisher 双尾 p=0.036）**；
三个旧 boss 回归 9/9 零死亡且普遍更快。**全部收益里，真正统计显著的只有一项**（目标接管），
其余四项只动了中间量——这本身就是最重要的一条经验。

## 一、通用方法（下一个 boss 直接照搬）

### 1. 先量化「改前口径」，再动手

每一项改动都必须先有一个**能复跑的脚本**把改前的数字打出来，并明确"改动要让哪个数字动"。
本轮最贵的教训是反过来的：凭"看起来像瓶颈"动手，跑两轮（约 45 分钟）才发现目标指标压根没动。

### 2. 新动作上线**先验执行率**，再开正式两轮

playerbots 是「每个 tick 只执行一个动作」的引擎，新动作最常见的失效方式不是逻辑错，是**排不上队**。
本轮三次白跑整轮就是这么来的：

| 事故 | 现象 |
|---|---|
| 坦克接小怪挂 26.5 | 触发器亮起的 15 个 tick 里执行 **0** 次（被 `tank assist`(50)/`tank face`(30) 抢光） |
| 神圣恳求挂 `ACTION_HIGH`(20) | 推入 381 次只执行 9 次（2.4%） |
| 英勇闸门用 `find target` | 潜地中的 boss 带 `UNIT_FLAG_NOT_SELECTABLE`、不进目标表，判据 fail-open，英勇照样早放 |

**做法**：改完先跑 1–2 场，`grep "A:<动作名> - OK"` 看计数；为 0 就先调相关性/判据，别开整轮。

已知相关性台阶（盗贼视角实测）：
`pull action` 105 / `loot roll` 100 / `drop target` 99 / `ACTION_EMERGENCY` 90 / **AN 层躲踏 60、保距 58** /
`dps assist`·`tank assist` 50 / `kick` 42 / `set facing`·`set behind` 37 / `tank face` 30 /
`fan of knives` 28 / `garrote` 27 / `hunger for blood`·`ambush` 26 / `envenom` 24 / `reach melee` 21 /
**`mutilate` 13** / `melee` 5。

`USELESS` **不吃 tick**（冷却中/buff 已在身上会直接跳过），所以给保命类动作抬高相关性是安全的。

### 3. tick 级统计法（定位"动作排不上队"的唯一办法）

按 bot 切 `--- AI Tick ---` 分段，统计：
- 该动作被 `PUSH` 的 tick 数 vs 出现 `A:<名> - OK` 的 tick 数；
- 没轮到它的那些 tick 里，**最后一个 `OK` 的动作是谁**（= 抢占者）。

本轮靠它定位到：盗贼主输出毁伤 303 次推入只有 **17% 轮得到**，抢占者里目标管理链占 46%。

### 4. 两轮五场才下结论，早停规则必须**事先声明**

5 场的击杀率差异几乎全在噪声里（本轮出现过同一改动 5/5 与 1/5 相邻两轮）。
序贯早停可以用（省时间），但规则要**事先写下**；本轮我犯过一次：看到中途两场团灭就想引用早停，
而第 3 场其实是击杀——**看着中途数据找理由停**就是滥用。

### 5. 共享层改动必须回归三个旧 boss

`heroic-nexus-keristrasza-disc-n5`、`heroic-uk-skarvald-dalronn-n5`、`heroic-nexus-anomalus-n5` 各 3 场。
回归不只是"没退化"，也可能是**正收益的证据**：目标接管那一轮回归 9/9 且阿诺玛鲁斯快了 30–60 秒，
反过来佐证了收益面是全副本而不是本 boss 调参。

## 二、引擎/共享层的系统性缺陷（对每个 boss 都成立）

### 已修（下一个 boss 直接受益，不必重查）

| 缺陷 | 表现 | 修法 |
|---|---|---|
| **目标一死要走四个 tick 才恢复输出** | `drop target`→`dps assist`→`reach melee`→`set facing`，实测 tick 0.69 秒 ≈ **2.8 秒不出手**；一场死 20 只小怪 ≈ 56 秒空转 | `DropTargetAction` 继承 `AttackAction`，同 tick 接管下一个目标（`2fa6cab8`）。**击杀率 40%→80%，p=0.036** |
| **面向判据比游戏严一倍** | `IsFacingValue` 用 `HasInArc(M_PI_2)`=±45°，核心自身判面向是 ±90°；灰带里反复触发 `set facing`（一场 198 次，每次还 `SetNextCheckDelay(100ms)`） | 改 ±85°（留 5° 余量）。`set facing` −39%、`NOT_INFRONT` 0 次 |
| **防骑的续蓝闭环断在第一环** | 神圣恳求挂 `HighManaTrigger`（蓝<65% 才亮）+ 相关性 20，推入 381 次只执行 9 次；恳求不在身上，圣光守护 2/2 每场 123 次 proc 全刷在空气上 | 新增「战斗中且恳求不在身上」触发器 + 相关性 52。坦克活着时法力地板占蓝池 50%→72%，全程不见底 |
| **治疗见底后队里还有一整池蓝没人用** | 坦克阵亡 39 次里 31 次是被小怪磨死、同刻牧师蓝中位 38，而元素萨满 18.5k 法力池整场只放 3.5 次治疗 | AN 层「治疗没蓝/阵亡且有人残血 → 非治疗职业补治疗波」。坦克消耗型阵亡 31→1 |
| 夹具：英勇疲惫跨场残留 | 疲惫(57723) 10 分钟 > 一场周期 5.3 分钟，下一场施法直接 `SPELL_FAILED_TARGET_AURASTATE(111)` | 开怪前清 57723/57724（`4beddea`）。**这也修正了"13 场没放英勇"的错误归因** |
| 夹具：打输了还空跑到超时 | 原本只有「全员死亡→wipe」「无人死亡且 boss 脱战→aborted」两条路径，萨满自复活独活时两条都不占 | 新增「有人阵亡 + boss 脱战回满血 + 残存者脱战 → 立即判 wipe」（`22107fd`），一次省约 200 秒 |
| **看不见队友＝队友不存在（治疗链）** | `PartyMemberToHeal::Check` 要求 `IsWithinLOS`，视线一断治疗目标为空 → 不治；而所有"走过去"的动作又都以同一个值为目标 → 连挪一步都不会。实测一段 20 秒：治疗满血、原地不动、法杖平A、法力还在回，18 码外的坦克被磨死 | 新增 `party member to heal no los` 取值只给「走过去」这条链用（触发器 + 接近动作），**施法仍用带视线的取值**（`9134211d`）。无视线占比 22%→3%、治疗频率 0.37→0.48 次/秒、德雷德 3/5→15/16 |
| **看不见队友＝队友不存在（`main tank`）** | `PartyMemberMainTankValue` 用基类 Check，坦克被柱子挡住那一秒 `main tank` 变空，所有 `if (!mainTank) return false;` 整组静默跳过：盗贼嫁祸/消失、法师隐形、牧师渐隐、给坦克的 buff、**以及"追敌不离主坦"那道护栏**（护栏恰好在最需要时关闭） | 覆写 `Check` 只去掉视线、保留同地图与距离判据（`5ef5adcc`）。非坦克位取不到主坦的战斗秒 **20%→0%**（法师 30%/萨满 27%/牧师 15%/盗贼 6%） |
| 框架：boss 开怪即进入不可攻击阶段就跑不起来 | `BeginAssistForAll` 要求每个跟随者都能对 boss 下 assist，而诺沃斯 P1 立刻挂 `NON_ATTACKABLE\|NOT_SELECTABLE`，`IsValidAttackTarget` 必然 false → 整场判 `not all followers entered combat`，一场都跑不起来 | boss 不可选中时放行跟随者、不代它们选目标（mod-raidtest）。阿努巴拉克潜地同族 |
| 框架：巡逻 boss 的开怪被一次性拒绝 | 开怪那一刻 boss 可能正好被柱子挡住或走出施法距离，`pull_rejected ... los=false` 直接作废——德雷德为此丢过两场 | 开怪被拒给 20 秒重试预算、逐 tick 重来，超预算才 abort（mod-raidtest） |

### 未修（**待办**，价值已量化）

> **注（2026-09-16）**：第 0 条（视线过滤）与第 0.5 条（治疗不给自己留手）**都已修**，
> 连同 `main tank` 那条同族缺陷一起搬到了上面的「已修」表；下面的原文保留供追溯。
> **当前真正未修的是第 1 条起。** 施法型取值（驱散/复活/团队 buff）仍按视线过滤是**刻意保留**的，
> 相关的新增功能见第六节待办第 0 条。

**0. 视线被当成"候选过滤条件"，看不见的队友等于不存在**（2026-09-15 因格瓦尔实测，**2026-09-16 已修** mod-playerbots `9134211d`，见本条末尾）

`PartyMemberValue::Check`（PartyMemberValue.cpp:113）和 `PartyMemberToHeal::Check`
（PartyMemberToHeal.cpp:135）都硬性要求 `IsWithinLOS`。后果不是"少治一次"，是**整条链条静默停摆**：
治疗的 `party member to heal`、法师的 `party member to dispel` 一起返回空 → 不治、不解；
而所有"走过去"的动作（`reach party member to heal` 等）又都以这同一个值为目标 → **连自救都做不到**。
实测一次团灭：治疗连续 10 个 tick `no actions executed`、法师同窗口零伤害 14 秒、
坦克 31 秒没收到任何治疗从满血被磨死。

**上游写过修法但够不到**（`RangeTriggers.cpp:193`）：

```cpp
bool PartyMemberToHealOutOfSpellRangeTrigger::IsActive()
{
    Unit* target = AI_VALUE(Unit*, "party member to heal");
    if (!target) return false;                    // ← 视线不通时就在这里返回了
    return ... || !bot->IsWithinLOSInMap(target); // ← 专门为视线写的分支，永远到不了
}
```

修法方向：给这个触发器和 `ReachPartyMemberToHealAction` 喂一个**不按视线过滤**的取值
（施法类动作仍用带视线的那个，免得隔墙施法），并让接近动作在"距离够但看不见"时也 `isUseful`
（现在它 `IsWithinCombatRange` 就返回 false）。**风险**：共享层、影响所有治疗职业，必须回归三个旧 boss。
因格瓦尔那一轮先在 boss 层验证了机制（新增 `ingvar regain los` 侧移绕遮挡，靶子指标从 9–17 秒归零）。

**共享层版本已做（2026-09-16，`codex/shared-heal-los-recovery` 的 `9134211d`）**，就按上面这个方向：
新增取值 `party member to heal no los`（同判据去掉 LOS）→ 触发器改用它 →
`ReachPartyMemberToHealAction` 覆写 `isUseful`/`Execute`，把「距离够但看不见」也算需要移动，
看不见时先靠到 8 码、已在 10 码内还看不见就靠到 2 码。**施法类动作仍用带视线的取值。**

- **坑**：靠近距离不能用 `distance`（治疗距离 40 码）——`ReachCombatTo` 一进门就判「已经够近」返回 false。
  第一版写成 `max(8, distance*0.5)` = 20 码，而治疗本来就站在 17–19 码，6 次推入 6 次 FAILED，一步没走。
- **效果**（英雄达克萨隆要塞 King Dred）：治疗与坦克之间的无视线占比 **22% → 3%**，最长无视线块 27 秒 → 6 秒，
  治疗频率 0.37 → 0.48 次/秒；击杀 3/5 → **15/16（94%，CI 72–99%）**，Fisher p=0.128（改前只有 5 场，不显著）。
- **回归 9/9**：凯利丝塔萨 3/3、斯卡瓦尔德&达隆 3/3 零死亡、阿诺玛鲁斯 3/3 零死亡。
- **同族第二条已做**（2026-09-16，`5ef5adcc`）：`main tank` 取值也不再按视线过滤。
  「谁是主坦」是事实，与看不看得见无关；取不到时 `if (!mainTank) return false;` 会让
  嫁祸/消失/隐形/渐隐、给坦克的 buff、以及"追敌不离主坦"护栏整组静默跳过。
  实测非坦克位取不到主坦的战斗秒 **20% → 0%**（法师 30% / 萨满 27% / 牧师 15% / 盗贼 6%）。
  量它用 mod-raidtest 的只读探针 `mt=`（每秒一采样，`9d36278`）。
- **仍未做**：施法型取值（`party member to dispel` / `to resurrect` / `without aura`）继续按视线过滤。
  **这是对的**——隔墙放不出驱散和 buff。它们缺的是像治疗那样的「走过去」链条，属于新增功能，不是修缺陷。

**0.5 治疗从不给自己留手**（2026-09-15 因格瓦尔实测，**已修** `20e3e2b0`）

`PartyMemberToHeal::Calculate` 的排序是 `probeValue = 血量% + 到自己的距离/10`。自己的距离项恒为 0，
坦克隔 25 码也只加 2.5，于是坦克长期以微弱优势压过自己（实测一刻：坦克 46+2.5=48.5 对自己 49+0=49），
**治疗永远是"第二低"，永远轮不到自己**。而戒律牧唯一的自保动作是 `critical health`(25%) 的痛苦压制。
实测十场：治疗在 50% 血以下停留 94 秒，其中只有 12 秒收到任何治疗（含 HoT 跳动），不是没蓝。
修法：自己是治疗、血量 <`mediumHealth`、且当前目标不危险（>`lowHealth`）时先治自己。
治疗阵亡场次 7/10→2/10（p=0.07），回归 9/9 零死亡。

**1. `PartyMemberToProtect::Calculate()` 第一行是 `return nullptr;`** —— 这是你记得的那条。

`src/Ai/Base/Value/PartyMemberToHeal.cpp:164`，函数整个被上游短路，下面 40 行是够不到的死代码。
`ProtectPartyMemberTrigger::IsActive()` 就是 `return AI_VALUE(Unit*, "party member to protect")`，
于是 **"protect party member" 这条触发器对所有职业永远不亮**，一次性废掉三个职业的保护链：

| 职业 | 被废掉的技能 | 接入点 |
|---|---|---|
| 圣骑士 | **保护之手**（1022，10 秒物理免疫） | `GenericPaladinStrategy.cpp:31`，相关性 `ACTION_EMERGENCY+3` |
| 牧师 | **给队友的痛苦压制**（−40%） | `HealPriestStrategy.cpp:118` |
| 战士 | 援护 intervene | `TankWarriorStrategy.cpp:324` |

实测 15 场：圣骑士三个"手"系技能（1022/6940/1038）**0 次使用**，技能都已学会（`character_spell` 里都在）。
牧师痛苦压制 0.3 次/场，全部来自"自己残血"那条（第 110 行），给队友的一次都没有。

**先看伤害学派再决定值不值得做**：保护之手是**纯物理免疫**。因格瓦尔那一轮查了 `Spell.dbc` 的
`SchoolMask`（字段下标 225，用火球/寒冰箭/惩击/腐蚀术标定）：Dreadful Roar 59734、Woe 反射 59736、
暗影斧 tick 42751、Dark Smash 59709 **全是暗影**，保护之手一个都挡不住，那条待办对该 boss 零头寸。
换 boss 前先读学派，别默认"保护链一定有用"。

**为什么在阿努巴拉克值得做**：两次团灭的起点都是"守卫咬住萨满/法师 10 秒打掉 14–23k"（505/2 法师 210s、505/3 萨满 63s），
保护之手正是这个场景的对症技能（守卫是物理近战）。而且死代码里的阈值也偏晚（坦克 ≤10%、其他 ≤30%），打开后还要调。
**风险**：这是共享层且影响三个职业，必须回归；`PartyMemberToProtect` 被短路可能有上游未记录的原因（先查 blame）。

**2. 盗贼/法师的循环仍远低于理论值**：目标接管之后毁伤仍只有约 23 次/场（理论 60–80）、能量堆满 24%、
毒伤 3.3→约 5 次/场（理论 20+）。抢占者里 `reach melee`(21) 没降。近战的"跑过去"仍占一整个 tick。

**3. 提速没做完**：并行多实例是唯一能改变节奏的一项（现在一轮 5 场 = 22 分钟，且**墙钟几乎全是战斗时间**）。
前置条件：`MapUpdate.Threads` 现在是 1，必须先验证"并发后 tick 间隔（现 0.69 秒）与击杀时间分布不变"，
否则等于换了个更差的被测对象。详见 [WORKFLOW 验证提速](WORKFLOW.md)。

## 三、口径陷阱清单（每一条都是本轮真踩过的）

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| **指标的分母不等于改动的作用域** | 「治疗自保」只在"治疗<65% 且无队友≤45%"这个约 5 秒/场的窗口里生效，用**全场**治疗落点分布去看，改前改后都是 16.3%——效应被稀释到看不见，一度写下"改动根本没生效"。按窗口重算是 12%→34% | 先写清楚改动**只在什么条件下生效**，指标的分母就取那个条件，别取全场 |
| **量触发器头寸时漏掉条件** | 算"萨满补位治疗"的窗口时只算了"没有能用的治疗 + 有人残血"，**没算补位者自己是否还活着且有蓝**，得出 9.9 秒/场、7/19 场；补齐后是 3.3 秒/场、5/19 场，实测 11 场触发 1 次、执行 0 次——团灭是级联的，治疗一倒补位者基本同时就没了 | 量一个触发器的头寸，就把它 `IsActive()` 里的**每一个条件**逐条放进过滤器，缺一个都会高估 |
| **从 tick 形状推机制** | 治疗死前出现成段 `no actions executed`，据此推断"被自己的 3 秒读条锁住"；加了 `casting=` 探针后实测：治疗存活期只有 **10%** 时间在读条，三次阵亡的死前 10 秒里合计只有 5 秒 | 引擎轨迹的"空"有多种成因（读条中 / 无触发 / 全被判 IMPOSSIBLE），**要区分就得加字段**，不能靠形状推；只读探针很便宜，先量再改 |
| **用刚跑完的一轮去给下一轮做取舍** | 按 534+535 那 10 场算出"萨满补位窗口从 10.4 秒/场缩到 3.2 秒/场、没有头寸"，据此砍掉了一个候选；按 19 场重算是 9.9 秒/场，**基本没变**——单轮噪声被直接传导进了决策 | 候选取舍用**累计样本**；或者至少等这一轮的率本身稳下来（CI 收窄）再算下一轮的头寸 |
| **运行中的 attempt 当成结果读** | `raidtest_attempts` 里正在跑的那一场是 `result=aborted, duration_ms=0` 的**占位行**；据此报过一次"3 场限流作废"，数据落定后其实全是击杀 | 读结果前先确认 run 已收尾（`raidtest_runs.finished_at IS NOT NULL`），别按行数判断 |
| **夹具只看"房间里有谁"** | 德雷德连续三次修正基线：0/5（两只巡逻精英晃进来）→ 2/5（还有一只**是机制要用到的迅猛龙的编队队长**，Raptor Call 拽一只就把它带进来）→ 3/5。前两次都得出了"完全打不过"的假结论 | 建夹具要另查两类：`creature.MovementType=2` 的巡逻路径（用 `creature_addon.path_id` → `waypoint_data` 算到战场的最近距离，别只看 spawn 点）、`creature_formations`（groupAI≠0 时拉一只等于拉一组） |

## 四、这个 boss 特有的结论（**不要**迁移到别的 boss）

- 三次潜地合计 ~127 秒不可压缩，且潜地期输出已有 90% 压在大型召唤物上——「守卫优先」没有头寸。
- 判别输赢的量是**180 秒时 boss 的血**（击杀场中位 24% / 失败场 41%），不是承伤（击杀场与失败场前 240 秒承伤一模一样，391k vs 392k）。
- 毒疗者是远程施法者，它打非坦克的 66–69k **嘲讽接不走**；可寻址的只有贴身近战。
- 「白给一次圣佑远好过该开时没开」：试过收紧（破甲≥5 + 读条剩 1.5 秒再开），run 515 直接 0/5、坦克五场全死。
- 近战站位本来就对（中位夹角 116°），32k 一击秒杀是那 19% 的偶发，只能靠读条期躲，不是默认站位问题。

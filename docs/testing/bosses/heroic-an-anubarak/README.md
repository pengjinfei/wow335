## ⚠️ 先纠正上一轮记错的结论

上一轮（run430）我把死因记成「戒律牧师开场把 GCD 花在 1 小时团队 buff 上」。**这是错的**，
那只是次要现象，且只出现在团灭之后的场次（团灭抹掉 buff、框架开怪前不补，bot 只能在战斗中补）。

真实死因是**场景坐标错误**，下面有完整证据链。

## 根因：远程被关在 boss 房门外，治疗因此选不到坦克

阿努巴拉克房间有三扇门 192396/192397/192398（`gameobject_template.type = 0` 实体门、
`Data0 = 1` 初始开启、尺寸 3.4–3.75），位于 **y ≈ 252.2–256.2**；实例脚本把它们登记为
`DOOR_TYPE_ROOM`，`boss_anubarak.cpp` 的 `EVENT_CLOSE_DOORS` 在开怪 **5 秒后**关闭。

boss 在 y = 248.3，即门的**南侧**。而我把准备点 (551, 280) 与开怪点 (551, 260) 都放在了
门的**北侧**。于是每场都是：坦克和盗贼进门内打 boss，治疗/法师/萨满留在门外 —— 门一关，
**三个远程与坦克之间没有视线**。

治疗侧的连锁反应（`PartyMemberToHeal.cpp:135` 的 `IsWithinLOSInMap`）：
坦克被过滤掉 → 队伍里唯一「可治疗」的只剩牧师自己 → 所有治疗动作退化成对自己施放 →
自己满血 → 全部 `IMPOSSIBLE`。

**逐 tick 轨迹实证**（run443，`LogInGroupOnly = 0`）：

```
target is immuned to spell - target name: Raidtebnfivc, spellid: 48066, bot name: Raidtebnfivc
Raidtebnfivc A:power word: shield - IMPOSSIBLE
Raidtebnfivc A:power word: shield on party - IMPOSSIBLE
```

（48066 是真言术：盾，撞的是牧师自己身上的虚弱灵魂。冷却类失败同样全是自己：
强效自愈 10060 ×35、愈合祈祷 48113 ×12、苦修 53007 ×7。）

采样证据（run443 a1）：牧师 `in_combat=true`、`hp=16500/16500`，
**法力一路从 15786 回到 16283**（= 完全没施法），从 10.7 秒到 102.5 秒空转 **92 秒**；
同期坦克从满血被磨到 0、**55.2 秒阵亡，全程一次治疗都没吃到**。
按角色分：坦克与盗贼（近战）全程活跃，治疗/法师/萨满三个远程在 20–80 秒几乎零施法。
萨满图腾落点（带 `dst=`）显示它整场停在 y ≈ 278–280，牧师位置采样固定在 (551.00, 280.00, 224.33)。

## ⚠️ 产生这个坐标的方法错误：`raidtest los` 的 z 用法

`raidtest los <map> <x1> <y1> <z1> <x2> <y2> <z2>` 里：

- `vmap_floor_from/to` 是从 **z+2 向下搜 50 码**找地面 —— 传偏高的 z 只是搜索起点，没问题；
- 但 **`los` 是从 `(x1,y1,z1+2)` 到 `(x2,y2,z2+2)` 量的**。

我勘测时传了 z1 = 240 而地面在 ≈ 223，等于**在离地 18 码处量视线**，墙沿、坑沿全越过去了，
整批 `los=true` 都是假的。按它选的第二版坐标 (551, 224) 用实测地面 221.65 复量是 `los=false`，
5/5 场 `pull_rejected`（日志：`los=false distance=12.88 leader_pos=(551,224,221.65)`）。

**正确做法是两步**：第一遍随便传个高 z 拿 `vmap_floor_from`，
第二遍**用拿到的地面高度当 z1** 重新量 los，只信第二遍。

另外，`raidtest los` 是**静态 vmap 探针，看不到战斗中才关上的门**。
boss 带 `DOOR_TYPE_ROOM` 门时，准备点与开怪点必须都在 boss 那一侧。

### ✅ 团灭后团队 buff 不恢复（已修）

`RestoreRoster` 原来只回满血蓝 + 复位冷却。团灭抹掉 1 小时团队 buff，bot 只好在下一场
**战斗中**补：run430 a2/a3 开场 1.7 / 3.8 / 10.1 / 18.4 秒连放四个团队 buff，而 a1
（登录后首场、buff 还在）没有这个现象。

新增 `RestoreStartingBuffs`：以本 run 第一场的长时效增益（永久或 ≥30 分钟、非被动、正面）
为参照态，之后每场补齐缺的；用 `AddAura` 直接补，不让 bot 施法。与既有「每场是独立单元测试、
起点一致」同一口径。日志证据：`re-applied 4 missing starting buff(s) before pull`。

### ✅ 穿刺闪避（已修，机制指标降 13 倍，但没提高击杀率）

上游 `ANStrategy` 的 TODO 写着「尖刺不是 gameobject 也不是触发器、瞬发没读条、追踪不到」。
**三条实测都不成立**：

- 它就是一只 creature（`Impale Target`，**entry 29184**），战斗日志里的 `actor_entry` 就是它；
- **有 4 秒预警窗口**。SmartAI(29184)：`t=0` 挂预警光环 53455 → `t=4000` 施放伤害
  53454（英雄 **59446**）→ `t=4200` 移除预警 → 7 秒后消失；
- **伤害半径只有 4.0 码**（SpellRadius idx 26），英雄档 **7,539** 点 + 击退。

实测效果：

| | 命中 | 承伤 | 战斗总时长 | 伤害/秒 |
|---|---|---|---|---|
| run448（无闪避） | 79 次 | 439,741 | 1,249.9 秒 | **351.8** |
| run449（有闪避） | **8 次** | **46,759** | 1,686.2 秒 | **27.7** |

**但击杀率没变（仍 1/5）。** 变化体现在别处：总战斗时长从 1,250 秒涨到 1,686 秒、
超时场次 1 → 2（480 秒分别停在 46% 和 73%）。**队伍活得更久，但输出没跟上** ——
瓶颈从「被打死」转移到了「打不动」。这条仍保留：正确打法、指标可验证、不引入回归。

### ❌ 转火守卫/毒疗者——假设被实测推翻，已回退（**别重走**）

**假设**：小怪从生成活到团灭（run445 a3：守卫 184 秒 / 154,181，毒疗者 113 秒 / 102,767，
合计是 boss 本体 91,857 的 2.8 倍），是因为没人转火；而它们不死，boss 就不提前上来
（`SummonedCreatureDies` 里 `_remainingLargeSummonsBeforeEmerge` 归零才把 EMERGE 提前到 5 秒），
穿刺又整段持续。照搬魔枢阿诺姆鲁斯的转火裂隙（那次 0/5 → 10 场 9 杀）应该能一并解决三件事。

**结果**：两种形状都是回归，而且**三种配置合计 15 场，大体型小怪一只都没被杀掉**（0/5、0/5、0/5）。

守卫的伤害打在谁身上：

| | 坦克 796 | 治疗 797 | 萨满 800 |
|---|---|---|---|
| run445（无转火） | **156 次 / 296,296（81%）** | 5 次 / 17,113 | 13 次 / 42,780 |
| run446（全队转火） | 49 次 / 109,416 | 19 次 / **101,270** | 16 次 / 56,999 |
| run447（坦克主导） | 25 次 / 46,750 | 9 次 / 41,652 | 37 次 / **123,679** |

**原基线里坦克本来就把守卫抓得很好**（81% 的伤害落在坦克身上）。转火破坏了一个已经正常运转的
仇恨安排，却一只小怪都没多杀掉——伤害只是从坦克挪到了布甲（法师 14,504 血挨过一下 10,487）。

**根因不是目标选择，是输出吃不下**：英雄守卫 31599 是 81 级、`HealthModifier = 5`
（boss 31610 是 38，约等于 boss 血量的 13%），而队伍还要同时打 boss。

**教训**：阿诺姆鲁斯的裂隙是**不还手的固定物**，仇恨无所谓，所以「全队各自转火」可行；
这里是**会打人的近战精英**，同样的形状直接把布甲打死。
**照搬先例前要先确认被转火的目标会不会还手。**
另可参照：本轮保留下来的穿刺闪避只加走位、不碰任何目标决策，就没有引入回归。

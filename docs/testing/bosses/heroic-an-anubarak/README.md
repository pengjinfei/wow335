## 根因：远程被关在 boss 房门外，治疗因此选不到坦克

阿努巴拉克房间有三扇门 192396/192397/192398（`gameobject_template.type = 0` 实体门、
`Data0 = 1` 初始开启、尺寸 3.4–3.75），位于 **y ≈ 252.2–256.2**；实例脚本把它们登记为
`DOOR_TYPE_ROOM`，`boss_anubarak.cpp` 的 `EVENT_CLOSE_DOORS` 在开怪 **5 秒后**关闭。

boss 在 y = 248.3，即门的**南侧**。而我把准备点 (551, 280) 与开怪点 (551, 260) 都放在了
门的**北侧**。于是每场都是：坦克和盗贼进门内打 boss，治疗/法师/萨满留在门外 —— 门一关，
**三个远程与坦克之间没有视线**。

治疗侧的连锁反应（`PartyMemberToHeal.cpp:135` 的 `IsWithinLOSInMap`）：
坦克被过滤掉 → 队伍里唯一「可治疗」的只剩牧师自己 → 所有治疗动作退化成对自己施放 →
自己满血 → 全部 `IMPOSSIBLE`。

**逐 tick 轨迹实证**（run443，`LogInGroupOnly = 0`）：

```
target is immuned to spell - target name: Raidtebnfivc, spellid: 48066, bot name: Raidtebnfivc
Raidtebnfivc A:power word: shield - IMPOSSIBLE
Raidtebnfivc A:power word: shield on party - IMPOSSIBLE
```

（48066 是真言术：盾，撞的是牧师自己身上的虚弱灵魂。冷却类失败同样全是自己：
强效自愈 10060 ×35、愈合祈祷 48113 ×12、苦修 53007 ×7。）

采样证据（run443 a1）：牧师 `in_combat=true`、`hp=16500/16500`，
**法力一路从 15786 回到 16283**（= 完全没施法），从 10.7 秒到 102.5 秒空转 **92 秒**；
同期坦克从满血被磨到 0、**55.2 秒阵亡，全程一次治疗都没吃到**。
按角色分：坦克与盗贼（近战）全程活跃，治疗/法师/萨满三个远程在 20–80 秒几乎零施法。
萨满图腾落点（带 `dst=`）显示它整场停在 y ≈ 278–280，牧师位置采样固定在 (551.00, 280.00, 224.33)。

## ⚠️ 产生这个坐标的方法错误：`raidtest los` 的 z 用法

`raidtest los <map> <x1> <y1> <z1> <x2> <y2> <z2>` 里：

- `vmap_floor_from/to` 是从 **z+2 向下搜 50 码**找地面 —— 传偏高的 z 只是搜索起点，没问题；
- 但 **`los` 是从 `(x1,y1,z1+2)` 到 `(x2,y2,z2+2)` 量的**。

我勘测时传了 z1 = 240 而地面在 ≈ 223，等于**在离地 18 码处量视线**，墙沿、坑沿全越过去了，
整批 `los=true` 都是假的。按它选的第二版坐标 (551, 224) 用实测地面 221.65 复量是 `los=false`，
5/5 场 `pull_rejected`（日志：`los=false distance=12.88 leader_pos=(551,224,221.65)`）。

**正确做法是两步**：第一遍随便传个高 z 拿 `vmap_floor_from`，
第二遍**用拿到的地面高度当 z1** 重新量 los，只信第二遍。

另外，`raidtest los` 是**静态 vmap 探针，看不到战斗中才关上的门**。
boss 带 `DOOR_TYPE_ROOM` 门时，准备点与开怪点必须都在 boss 那一侧。

### ✅ 践踏的真实机制（上一轮和本轮前半段都搞错了）

`DoCast(target, SPELL_POUND)`，英雄版 **59433**：

- `EffectImplicitTargetA = 24` → `SpellInfo.cpp:237` 是 **`TARGET_UNIT_CONE_ENEMY_24`**
  （CONE / DIR_FRONT），**不是圆形区域**
- `Spell.cpp:1251` 对该目标类型写死 `cone_degrees = 24`，`Position::HasInArc` 取半角
  → **±12°**；`EffectRadiusIndex` 给出锥长 **15 码**
- boss 在 `DoCast` **之前**先 `SELF_ROOT` + `DisableRotate(3300ms)`，读条期间锥向锁死
- `spell_azjol_nerub_pound` 对每个命中者补 59432，**满额不分摊**（BasePoints 47,124）
- `IsWithinBoundaryRadius` 不是漏洞：玩家 `UNIT_FIELD_BOUNDINGRADIUS` ≈ 0.4，
  取 `max(…, MIN_MELEE_REACH = 2.0)`，只有站在 boss 原点 2 码内才无视角度

实测单次伤害：坦克 15,551–19,973（扛得住），布甲 27,502 / 32,603 / 35,953 / 37,154 /
40,664（约 2.5 倍血量上限，必死）。

### 结论

1. **缺陷文档「92% 读条治疗被移动打掉」的归因不成立。** 读条治疗放不出来的主因是瞬发（盾/恢复/愈合祷言）
   先占 GCD、读条治疗被评估时撞上 GCD 或苦修引导——这是策略优先级与 GCD 争用，不是移动。
   "移动中"只占可归因拒绝的 ~7%，且几乎全是穿刺击飞/躲刺这类**不该让路**的场景。
2. 修复本身行为正确（拒绝只发生在保命/被击飞时，无一次误让路），但在这个 boss 上**没有可观测收益**；
   击杀率 1/5 → 0/5 在本场景的历史波动（0/5、2/2、1/5）之内，不构成回归证据。
3. **FAILED 的原因仍是黑箱**：run 459 牧师所有治疗（含瞬发）的 FAILED 都比 457 高 3–5 倍，而瞬发不经过任何移动闸，
   说明 FAILED 来自 `Spell::prepare` 的其它拒绝码（视线/距离/目标状态……），两轮之间的差异是环境波动而非改动。
   缺陷文档当初就是把 FAILED 全算成移动。**下一步先给 `CastSpell` 的 prepare 失败补上结果码日志**（现有注释掉的

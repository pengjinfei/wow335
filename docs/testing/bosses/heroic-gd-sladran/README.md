### 3. 上游乘子在英雄难度是反效果（待量化，**先别改**）

```cpp
if (!botAI->IsDps(bot)) { return 1.0f; }
if (action->getThreatType() == Action::ActionThreatType::Aoe) { return 0.0f; }   // ← 全程禁 DPS 的 AOE
```

对「每 3–5 秒刷 3 只」的场面，**全程禁 AoE** 正好是反的；而「有包裹时禁止 `dps assist`」

## 三个头寸的量化结果（run 581，2 场，`LogInGroupOnly=0` 的 tick 级日志）

口径：`heroic-gd-sladran-disc-n5` 两场（87.9s 团灭 34% / 85.4s 团灭 35%，与 5 场基线一致），
`Playerbots.log` 41,159 行，按 `--- AI Tick ---` 切段统计。
**关键便利**：引擎会明写 `Multiplier slad'ran made action <X> useless`，
所以「被乘子归零」与「施法失败」**可以精确分离**，不必像 LESSONS 里担心的那样靠 `IMPOSSIBLE` 猜。

### 头寸 1：Snake Wrap 在场占比 ≈ 44–46%，`dps assist` 被归零 68–78%

| bot | 战斗 tick | 包裹在场的 tick | 占比 | `dps assist` 推入 | 其中被乘子归零 | 实际执行 |
|---|---|---|---|---|---|---|
| 法师 | 207 | 95 | **46%** | 92 | **70（76%）** | 2 |
| 盗贼 | 250 | 109 | **44%** | 118 | **80（68%）** | 8 |
| 萨满 | 179 | 78 | **44%** | 77 | **60（78%）** | 2 |

**代价量出来了**（按 `CanCastSpell Check Failed` 行里的 `target name` 还原每 tick 的当前目标）：

| bot | 有包裹时目标是 boss | 无包裹时目标是 boss |
|---|---|---|
| 法师 | **0 / 17 = 0%** | 32 / 41 = 78% |
| 盗贼 | **0 / 68 = 0%** | 38 / 68 = 56% |
| 萨满 | **0 / 26 = 0%** | 19 / 33 = 58% |

也就是说：**场上只要存在一个包裹（占战斗时间 44–46%），三个 DPS 的输出就 100% 不在 boss 身上。**

⚠ **一条被自己数据否掉的假设**：我原以为这会造成空转（没目标可切 → 无动作可执行）。
实测「包裹在场 vs 不在场」的空 tick 率是 法师 59% vs 47%、盗贼 34% vs 36%、萨满 37% vs 31%
——**没有显著差异**。空转是另一个独立问题（法师全场 52% 的 tick 什么都没执行），
与斯拉德兰无关，**不要记到这条账上**。

### 头寸 2：DPS 的 AoE 两场被归零 462 次，实际释放 5 次

| bot | 动作 | PUSH | **被乘子归零** | IMPOSSIBLE | USELESS | **OK** |

| 盗贼 | fan of knives | 278 | **66** | 66 | 17 | 1 |

**暴风雪 / 烈焰风暴 / 刀扇三项的 `IMPOSSIBLE` 计数与「被乘子归零」计数完全相等**

所以可以断定：**乘子是法师整场不放暴风雪和烈焰风暴的唯一原因**，

- **它是冗余的**：`attack snake wrap` 的相关性 **64** 本来就压过 `dps assist` 的 **50**，
  相关性排序已经保证「有包裹先打包裹」，不需要再用乘子去禁目标获取。

⚠ 风险：打包裹本身是正确打法（每场 ≈9 个 × 8,239 血 ≈ 74k 输出），
删掉之后要盯住「包裹被放着不管导致队友长时间被困」这个反向指标，
**对照指标里要加一条「包裹从出现到死亡的时长」**。

### 判读：改动生效了，但生效的方式是净负面

- **靶子指标动了**：boss 输出占比 38.9% → **52.2%**。这条改动确实做到了它要做的事。
- **我动手前提的那个理论顾虑（目标抖动）是错的**：主目标变化率反而从 44% 降到 33%。
  `attack snake wrap` 与 `dps assist` 并没有互相抢。**记下来，别再用这个理由否方案。**
- **但代价更大**：包裹被打死从 3.9/场 掉到 **0.8/场**——包裹基本没人管了。
  被包裹的人出不来，于是**场次时长 −19%（95.1s → 77.3s）**，
  boss 每秒输出**一点没涨**（2,345 → 2,373/s），每场打到 boss 的绝对伤害反而 **−17%**。
- 也就是说：**占比涨是因为分母塌了，不是因为分子涨了。**（口径陷阱：占比类指标必须配着绝对值一起看。）

**决定：回退第二刀，保留第一刀。** 上游那条 `Prevent auto-target acquisition during snake wraps`
是对的——只是它的理由不是我以为的「防抖动」，而是**「不让 DPS 半路丢下包裹」**。

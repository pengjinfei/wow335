## 场景设计与三次翻车（**别重走**）

最终配置：准备点 (-500,-735,30.3)、开怪点 (-536,-690,30.3)、
`PrerequisiteSpawns = 127454`、`FixtureDespawnSpawns = 127452,127413,127414,127415,127453,127455`。

1. **run 552**：前置列了四只迅猛龙。清完东南两只后队伍北上打 127453，路径必然穿过 boss 的
   22 码仇恨半径 → 61 秒 boss 自己进战斗，`prerequisite_invalid: boss engaged before clearing`。
   **北边那两只在不进仇恨半径的前提下够不着。**
2. **run 554**：前置收到两只、清怪 35–40 秒成功，但开怪被拒：
   `pull_rejected ... los=false`，boss 位置 (-539.2,-668.7)——**德雷德会巡逻**，
   出生点 (-544.9,-697) 只是他路过的位置。开怪点换成对整条巡逻线都有视线的 **(-536,-690)**
   （对 (-544.9,-697)/(-539.2,-668.7)/(-541,-710)/(-535,-655) 四点实测全 los=true）。
3. **run 556**：五场全部 `prerequisite_invalid: boss entered combat during recovery`——
   清完怪后队伍就站在他巡逻线旁边（127413 距他巡逻点只有 17 码），恢复窗口里他自己走过来。
   → 前置只留最东边的 127454（距巡逻线 ≥25 码），其余六只在 pull 那一刻由夹具移除。

**为什么必须留一只前置**：框架里只有走过「前置清怪 → 恢复」这条路，恢复结束时才会
把队伍**传送**到开怪点（`AttemptRunner.cpp` 的 Recovery → BossPosition）。没有前置怪的场景，
队伍会停在准备点开怪；而这里准备点离 boss 58.8 码，根本开不了。**这条对以后每个
「准备点必须远离 boss」的新场景都成立。**

口径：**隔离 boss 战（夹具移除六只迅猛龙）**。真人打法本来也是先把房间清光再拉 boss，
所以夹具移除与「已清完」在效果上等价；但结论仍按隔离形态记账。

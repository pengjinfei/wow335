## 3. 现在卡在哪（数据口径见第十九、二十轮）

失败几乎全部落在 **boss 11–25%、220–260 秒**这道墙上，机制类死法已经很少：
1. **牧师末段 OOM**：药水/暗影魔/心灵专注/希望圣歌每场都用，蓝仍在 215–245 s 见底，击杀要 250–280 s。结构性：要减少承伤或缩短战斗。
2. **守卫/毒疗者打非坦克**：第二十一轮已给坦克加了主动接怪（守卫段数 −17%、非坦死亡 −23%），但只解决了守卫那半边；**毒疗者的 66–69k/场接不走**（远程施法者，嘲讽只按 3 秒、毒箭齐射是 AOE）。守卫单刀 5–8.5k，萨满/法师 14–16k 血。
3. **破甲叠层后的 25k+ 践踏秒坦克**：圣佑 2 分钟冷却盖不住每一记。牧师有痛苦压制（3 分钟）可错开。
4. **英勇时机**：共享层 `BoostTrigger`（balance≤50）决定，39 场里 13 场没放、17 场落在第二次潜地附近。
5. 保距在开怪前 boss 被拉到西沿时仍有 no_candidate（候选半径 22 太小，可放到 24）。

## 6. 今天学到的操作与分析坑（新会话别再踩）

- **编译前必须征得同意**，用 `nice -n 10 cmake --build var/build/obj --target worldserver -j4`；改 AN 层 1–6 个 TU，改圣骑士 `PaladinActions.h` 一系 17 个 TU，改 `ReachTargetActions.h`/`PlayerbotAI.cpp` 约 31–34 个 TU。**只看 build log 里的 `error:`，别信 `echo exit=$?`。**
- **重启**：`bash scripts/restart_world.sh <logname>`（已修 `set -u` bug）；启动后第一条 FIFO 命令常被吞，重试并核对 `raidtest_attempts` 出现新 run_id。跑前 `DELETE FROM account_instance_times`。
- **判引擎状态**看策略快照（`heal_strategies` 含 "attack tagged"/"loot" = 非战斗集合）或动作名（`check mount state`/`follow`/`add gathering loot`），**不能看 resource 行的 in_combat**。
- **引擎日志把 relevance≤0（Multiplier 归零）也记成 IMPOSSIBLE**，不等于施法失败。
- **践踏 `spell` 行的 `cast:` 是读条完成时落库**，读条起点 = 命中时间 − 3.2 s；读条期 boss 服务端朝向可信（`FocusTarget → SetInFront`）。
- **tick 级统计法**：按 bot 切 `--- AI Tick ---`，统计"触发器出现但动作没有 A: 行"的 tick 里谁 OK 了——定位相关性抢占的唯一办法。
- **新动作上线先验相关性，再跑整轮**：第二十一轮第一版挂 26.5，触发器亮起的 15 个 tick 里执行 0 次（被 `pull action`105 / `tank assist`50 / `tank face`30 / `hand of reckoning`27 抢光），白跑一个 run。坦克侧要压过 `tank assist`(50)。`USELESS` 不吃 tick，所以高相关性不会挤占别的动作。
- **攻击性 reach 与治疗 reach 要分开**（`ChasesEnemy()`），追敌上限锚点：非坦克看主坦、坦克看治疗。
- 后台等待用 `Monitor`/detached `nohup` 脚本 + 数据库轮询，不要在前台 sleep；脚本里路径要绝对（`restart_world.sh` 相对路径踩过一次）。
- 分析脚本：`docs/testing/bosses/heroic-an-anubarak/evidence/healer_lure_stats.py <run...>`（北上/接手统计）；本地日志 `evidence/playerbots-run4xx.log.gz`（.gitignore）。

## 共享层：「谁是主坦」不再按视线过滤（2026-09-16 夜，mod-playerbots `5ef5adcc`，run 570–575）：非坦克位取不到主坦的时间 **20% → 0%**

同一族缺陷的第二条。`PartyMemberValue::Check` 把 `IsWithinLOS` 当候选过滤条件，
而 `PartyMemberMainTankValue` 用的正是这个基类判据——坦克被柱子挡住的那一秒，
`main tank` 返回空，所有 `if (!mainTank) return false;` 的行为**整组静默跳过**，
引擎日志里连 PUSH 行都没有：

- 盗贼的嫁祸于人（`tricks of the trade on main tank`）与 medium threat 的消失
- 法师隐形、牧师渐隐、猎人假死（同一族 threat 触发器）
- `BuffOnMainTank`：给坦克的 buff
- **共享层"非坦克追敌不离主坦"那道护栏**：`ChaseAnchor()` 取的就是这个值，取不到 →
  `IsChaseLeashed` 返回 false = **护栏恰好在看不见坦克时关闭**，而那正是最容易跑丢的时候

**先量后改**（mod-raidtest `9d36278` 加了只读探针 `mt=`，每秒记该 bot 能否解出 main tank）。
英雄德雷德，已剔除坦克阵亡后的采样：

| | 采样（战斗中·存活） | 取不到主坦 | 占比 |
|---|---|---|---|
| 改前 run 570 | 848（非坦克四人） | 166 | **20%**（法师 30% / 萨满 27% / 牧师 15% / 盗贼 6%） |
| 改后 run 571 | 792 | **0** | **0%** |

改法：`PartyMemberMainTankValue` 覆写 `Check`，**只去掉视线**，保留同地图与距离判据。
「谁是主坦」是事实，与看不看得见无关。**施法型取值（驱散/复活/团队 buff）一行未动**——
那些确实需要视线，隔墙放不出去。

结果：德雷德 **7/7**（run 571 + 575，五场里四场零死亡）。**单独效应无法从击杀率里分离**——
上一版（治疗视线修复）已经是 15/16，这一条只能按中间量记账。
回归三个旧 boss **9/9 击杀**：凯利丝塔萨 3/3（124.5/125.1/127.9 秒，a1 死 3 人）、
斯卡瓦尔德&达隆 3/3 零死亡（91.4/107.3/116.5 秒）、阿诺玛鲁斯 3/3（160.3/197.5/**275.9** 秒，共 1 死）。
阿诺玛鲁斯那场 275.9 秒比同日改前那轮（153–195 秒）慢，**单场样本，分不清噪声还是回退**，记在这里备查。

**口径陷阱（本轮又踩一次）**：运行中的 attempt 在 `raidtest_attempts` 里是 `result=aborted, duration=0`
的**占位行**，我按它报过一次"3 场限流作废"，数据落定后其实全是击杀。读结果必须等 run 收尾
（`raidtest_runs.finished_at IS NOT NULL`）。

## 共享层：治疗看不见队友时会走过去了（2026-09-16 傍晚，mod-playerbots `9134211d`，run 563–568）：**德雷德 3/5 → 15/16**，回归 9/9

修的是 [LESSONS](LESSONS.md) 里排第 0 条、一直标着「未修」的那个缺陷：`PartyMemberToHeal::Check`
硬性要求 `IsWithinLOS`，视线一断治疗目标就是空——不治；而所有"走过去"的动作又都以同一个值为目标，
于是治疗连挪一步都不会。上游在 `PartyMemberToHealOutOfSpellRangeTrigger` 里写过
`|| !IsWithinLOSInMap(target)` 这条分支，但第一行取的值已经按视线过滤过，那条分支一直是死代码。

改法（只动「走过去」这条链，**施法仍用带视线的取值**）：新增取值 `party member to heal no los` →
触发器改用它 → `ReachPartyMemberToHealAction` 覆写 `isUseful`/`Execute`，把「距离够但看不见」
也算需要移动，看不见时先靠到 8 码、已在 10 码内还看不见就靠到 2 码。

| 指标 | 改前（run 560） | 改后（run 563/567/568） |
|---|---|---|
| 治疗↔坦克 无视线占比 | **22%**（70/323 秒） | **3%**（14/415 秒） |
| 最长无视线块 | 27 秒 | **6 秒** |
| 治疗频率（全场） | 0.37 次/秒 | **0.48 次/秒** |
| 击杀 | 3/5 = 60%（CI 23–88%） | **15/16 = 94%（CI 72–99%）** |

**Fisher 双尾 p = 0.128，结果指标不显著**——改前那一臂只有 5 场，样本受限。按「中间量动了、
结果率样本不足」记账；补改前样本需要把二进制切回去，本轮没做。

**回归三个旧 boss 9/9 击杀**：凯利丝塔萨 3/3（119.9/125.0/136.2 秒，1 死）、
斯卡瓦尔德&达隆 3/3 零死亡（92.4/93.5/100.4 秒）、阿诺玛鲁斯 3/3 零死亡（153.1/171.2/195.1 秒），
时长都在历史区间内、无误拦。

**踩过一次的坑**：靠近距离不能用 `distance`（治疗距离 40 码），`ReachCombatTo` 会判「已经够近」
直接返回 false——第一版 20 码，实测 6 次推入 6 次 FAILED、一步没走。**按 LESSONS「新动作先验执行率」
冒烟一轮就发现了**，没有白跑整轮。

**同族未做**：`PartyMemberValue::Check`（法师 `party member to dispel` 等）仍按视线过滤。

## 英雄达克萨隆要塞 / 恐怖之王德雷德 第二轮（2026-09-16 下午，run 558–560）：**昨晚的 0/5 作废，干净基线 3/5**；恐惧被证伪，判别量是小怪存活

用户指定「先量恐惧结界和战栗图腾」。量了，**是零**：两场（其中一场完整 107 秒战斗、6614 条 PUSH）的
Playerbots.log 里 `fear ward` / `tremor` 出现 **0 次**，连触发器都没亮。根因结构性：牧师的
`FearWardTrigger`/`CastFearWardAction` 在引擎里存在但**没有任何 class 策略推它**（全仓只有 BWL/TK/海加尔
三个团本脚本显式调用）；萨满的土图腾槽默认不是 `tremor`（实测跑 `stoneskin totem`）。

**但恐惧不是打不过的原因。** run 560 五场：恐惧次数与时间点在击杀场和团灭场完全一致（6–7 次），
而三场**零死亡**的击杀同样吃满了恐惧。真正的判别量是**被 Raptor Call 拽来的迅猛龙活多久**：

| | 输出总量 | 迅猛龙造成的伤害 |
|---|---|---|
| 三场击杀 | 622k–630k | **14k / 20k / 40k** |
| 两场团灭 | 458k–498k | **74k / 72k** |

**昨晚那个 0/5 作废**——战场里混进了不属于遭遇战的巡逻精英。夹具三次收紧，每次都换来一次基线修正：
0/5（含 127442/127443 两只巡逻 Risen Drakkari Handler）→ 2/5（仍含 127444）→ **3/5（当前）**。
其中 **127444 是 127456/127457 两只迅猛龙的编队队长**（`creature_formations`，groupAI=512）：
Raptor Call 从 100 码外拽一只迅猛龙，编队把这只精英一起带进来，每场 50–63 秒准时出现、打 17k–52k。
队长移除、迅猛龙保留，Raptor Call 的弹药还在，机制不被削。

**通用教训（写进换本清单）**：`FixtureDespawnSpawns` 不能只看「房间里有谁」，还要查
(a) 谁会巡逻进来（`creature.MovementType=2` + `waypoint_data` 算最近距离）、
(b) 谁跟机制要用的怪同编队（`creature_formations`，groupAI≠0 时拉一只等于拉一组）。

**框架改动（本轮第二次编译）**：开怪被拒时给 20 秒重试预算逐 tick 重来，超预算才作废
（`AttemptRunner::StartBossPull`）。巡逻 boss 那一刻被柱子挡住或走出施法距离不等于开不了怪——
德雷德为此丢过两场。同轮把开怪点换成 **(-551,-685)**：它是实测唯一对德雷德全部 8 个 waypoint
都有视线的点（巡逻路径 `waypoint_data` id 1275070，14 点）。run 560 五场重试一次都没触发。

**下一轮靶子**：迅猛龙进场后多久被接手/打死——目标切换链（`drop target` → `dps assist` → 坦克接怪），
用 `LogInGroupOnly=0` 的 tick 级统计先量，不需要编译。详见 [德雷德记录](bosses/heroic-dtk-dred/README.md)。

## 英雄达克萨隆要塞 / 召唤者诺沃斯（2026-09-16 凌晨，run 548–550）：**5 次有效尝试全击杀零死亡**；修掉框架一道开怪门禁

新场景 `heroic-dtk-novos-n5`（准备点用上游 `NOVOS_PARTY_POSITION` (-378.85,-760.35,28.59)、开怪点 (-379,-748,27.71)、无前置怪）。

**框架缺陷（已修，mod-raidtest `CombatTrigger.cpp` +20 行，本轮唯一编译）**：诺沃斯 `JustEngagedWith`
立刻挂 `NON_ATTACKABLE|NOT_SELECTABLE` 进 P1，而 `BeginAssistForAll` 要求每个跟随者都能对 boss 下 assist，
`IsValidAttackTarget` 必然 false → `pull failed (not all followers entered combat)`，run 548 一场都跑不起来。
修法：boss 不可选中时放行跟随者、不代它们选目标。**对任何「开怪即进不可攻击阶段」的 boss 都成立。**

修后：冒烟 run 549 147.6 秒击杀；基线 run 550 五场 **4 击杀 / 0 团灭 / 1 场框架作废**，零死亡，140–148 秒。

与 boss 本体的 80k–133k 同量级；四只水晶操控者由 bot 自主清掉进 P2，框架没有做任何指派。

**框架缺陷二（未修）**：run550/seq4 `pull_rejected ... valid=false`——新实例里 boss 还带着不可攻击标志
就发了开怪，5 场丢 1 场。`clean boss spawn` 校验只确认 spawn 在、活着，没确认可被攻击。
候选修法：开怪前若 boss 不可选中就等几个 tick 再判。

判定：**正常规则通关（隔离 boss 战口径）**，bot 策略一行未改。详见 [诺沃斯记录](bosses/heroic-dtk-novos/README.md)。

## 「bot 不喝水」根因更正并修复：不是不会喝，是阈值错配（2026-09-11）

**2026-09-10 记的「bot 在战斗外低于 LowMana 阈值仍不喝水」这个描述不准确，此处更正。**
bot 会喝水、喝水也有效；缺的是**该喝的时机**。

`UseFoodStrategy` 的非 cheat 分支用 `"low mana"`（< `AiPlayerbot.LowMana`，默认 **15**）与
`"low health"`（< `LowHealth`，默认 **45**）；而 cheat 分支用 `"high mana"`
（< `HighMana`，默认 **65**）与 `"medium health"`（< `MediumHealth`，默认 **65**）。
于是不开 food cheat 时，**15%–65% 法力 / 45%–65% 血量这两段，bot 背着水和食物也不用**，
只能按脱战基础回复干等；而框架恢复门禁要的正是 65%。
开不开 food cheat 的差别本该只是水和食物**要不要白给**，而不是**什么时候该吃喝**。

**缺陷证据（run378）**：戒律牧从 22.4% 法力起，105 秒恢复窗口里**一次没喝**，
法力曲线是 1,181/15 秒 = **78.7/s 的完美直线**（纯脱战基础回复，无喝水加速段）；
**同场**法师在 15% 以下喝了一次，15 秒内从 22.7% 冲过 65%（约 **392/s**）。
即喝水机制本身是好的。另查 45 个 run 的事件：喝水法术 43183 共 8 次、食物 43180 共 1 次。

**修复**（mod-playerbots `codex/bot-drink-out-of-combat` @ `f0b090c6`，已推 fork `mine`）：
非 cheat 分支改用与 cheat 分支相同的 `"high mana"` / `"medium health"`。
装备档位、难度、`BotCheats` 均未变；用的是 roster 本来就配的 20 个蜜风茶(33445)与
20 份食物(33443)，**不是框架补资源**。

**对照（英雄魔枢泰蕾斯特拉，恢复耗时 = `recovery_complete` 的毫秒值）**：

| | 样本 | 喝水次数 |
|---|---|---|
| 修复前 run353/354/357 | 38.4 / 42.4 / 48.0 / 71.6 / 80.8 / **113.8** 秒 | 全程 **0** |
| 修复后 run379/382 | **3 毫秒 / 16.5 / 33.2 / 33.7 / 38.4** 秒 | 0–4 |

最坏值 113.8 → **38.4 秒**，框架 120 秒预算从「差 6 秒撞穿」变成约 3 倍余量。
此前被这条撞穿过两次：run322/attempt1、run378 的 `natural recovery timeout`。

**两点未验证，如实记录**：
1. **食物那一半没有单独对照。** run380（只改喝水）出现过「全队法力够、但有人血量在
   45%–65%，恢复白等 11.8 / 12.2 秒且零进食」，正是同一类错配；但改完之后 run381/382
   没人再落进那个血量区间（恢复 3 毫秒、0 次进食），**情况未复现**。
2. **修复后仍有 33–38 秒的恢复样本，且当时在喝水**，原因未查（喝水光环是否被移动打断？）。

**副作用需要注意**：`drink`/`food` 动作优先级 3.0，高于非战斗引擎里的 `follow`/`travel`（1.0）。
在副本夹具里 bot 是站定的，没有影响；但世界里赶路的 bot 低于 65% 时会坐下来喝水，
这是**跨内容的行为改变**，本轮没有量化。

1. **打断治疗：机制本来就有，但这两个治疗打不断。**

   失败机制：规则把 DPS 锁到坦克没抓的怪上，abort 场次由每场 1 死升到 **2–3 死**。

   表面数字是奥莫洛克 4/5、泰蕾斯特拉 1/5，但复查施法间隔后确认**变形术那一半测坏了**：
   78 次施放的间隔恒定 **1394–1413 毫秒**（= 急速后读条时间）、反复打同一只，
   `cast_cancel` 12 条全是 `by_self=false` 的半截读条——**羊从未上身**，法师在

   对照之下**妖术（瞬发）完全正常**：run373 五场各 **恰好 1 次**，之后被正确跳过，
   1 次 GCD 换一只治疗出局。
   => **「控制无效」没有被证实**；正确的重测是**只用妖术的纯瞬发版**。
   顺带确认：共享 `CcTargetValue` 里「AoE 团里的怪不 CC」**是正确默认**，不该动。

Steward、Crystalline Tender 都是 **7 人型**（羊/妖术/闷棍/致盲均可），

# 整本通关与 AI 带队：设计

更新：2026-09-29。状态：**设计稿，未实现**。计划在纳克萨玛斯 10 人收尾后开工，从 5 人本开始。

## 目标

真人只操作一个角色，由 AI 带队从副本入口一路打到尾王：坦克自己寻路、选怪、开怪，团长（AI 或真人）
开怪前分配站位与职责并用标记和宣布告知全队，bot 按分工执行，真人按宣布走位。

验收口径沿用现有做法：raidtest 可重复场景 + 真人实机（[HUMAN-SESSION](testing/HUMAN-SESSION.md)）。

## 现状：已有的积木

| 能力 | 现有实现 | 用处 |
|---|---|---|
| 单 boss 可重复测试 | raidtest 场景（准备点、开怪、击杀判据、观察器） | 验证 boss 段 |
| 开怪前按人摆位 | raidtest `SlotPreparation.N` | 相当于团长摆位，但只在框架里 |
| 前置清怪 | raidtest `PrerequisiteSpawns`、`PrerequisiteRepullDelaySeconds` | 清 boss 前的怪；已踩过「遭遇自己派怪」 |
| 清怪控制链 | [TRASH-CC-PULL-DESIGN](testing/TRASH-CC-PULL-DESIGN.md)（坦克发控制信令 → 控制 → 开怪 → 不放 AoE） | 拉怪决策的一部分 |
| 防掉层 | playerbots `IsSameFloorDestination`、`LiftSunkenDestination`（`1c2bf120`） | 寻路落点被吸到下层 / 目标陷在地面下 |
| 掉落与卡住诊断 | raidtest `fall_detect`（`2613eab`）、卡住中止与复位判定 | 自动寻路的回归指标 |
| 视线/地面探针 | `raidtest los` | 勘测站位、开怪点 |
| 按标记选目标 | playerbots `rti`、`pull rti target` | 击杀顺序、控制目标 |
| 位置指令 | playerbots `go`、`stay`、`follow`、`position`、`formation` | 真人手动指挥的现有手段 |
| 野外旅行节点图 | playerbots `Mgr/Travel/TravelMgr`、`TravelNode` | 待查：能否覆盖副本内部，能否复用为路线图 |

缺的是把这些串起来的四样东西：**副本路线数据、坦克导航与拉怪循环、分工（指挥链）层、真人协作规则**。

## 一、副本路线数据

每个副本一份路线文件。路线由 bot 的导航与拉怪使用，按框架边界归 playerbots（真人带 bot 时也要用），
raidtest 的「整本通关」场景只引用它：

- **路段**：入口 → 各组怪 → 各 boss 的有序节点，节点带坐标、是否休息点、是否必清。
- **怪组**：刷怪表 spawn id 集合、中心点、仇恨半径估计、巡逻路径（有则记录）、推荐开怪点与拉回点（拐角、断视线点）、推荐控制目标与击杀顺序。
- **boss 段**：引用现有 boss 场景（准备点、各阶段站位、分工模板），不重复定义。
- **特殊段**：门（gameobject 与开启条件）、升降梯/交通工具、载具、脚本事件（护送、连续刷怪通道）。

生成方式（三者组合）：

1. **自动初稿**：从 `creature` 表取副本内全部刷怪，按距离聚类成组；boss 列表取实例脚本 / 遭遇数据。
2. **导航校验**：用导航网格把相邻节点连起来，逐段 `PathGenerator` 验证可达、同层、无大落差；不通的段标红待人工。
3. **真人录制校正**：新增只读 GM 命令，真人跑一遍时按固定间隔记录位置与战斗开始/结束点，用来修正开怪点和路线。

## 二、坦克导航与拉怪循环

坦克（或当前领队）的主循环：

```
while 路线未完:
    段 = 下一段
    if 段是怪组:  准备检查 → 标记/控制 → 开怪 → 战斗 → 战后恢复
    if 段是 boss: 准备检查 → 分工下达 → 进 boss 场景流程
    else:         沿导航路径移动到下一节点（队伍跟随）
```

**导航执行**：逐段寻路，内置已踩过的坑：同层守卫、陷地目标抬高、掉落检测、卡住恢复（原地重寻路 → 退回上一节点 → 报告卡住），门与交通工具的状态检查，视线断续时不丢目标（四骑士台沿）。

**准备检查**（开怪前的门禁）：全队血量/蓝量阈值、有人死亡先复活、关键技能冷却、队伍在领队附近；有真人时额外等真人（见第四节）。

**开怪方式**：

- 视线拉（远程拉到拐角后面，等怪过来）、直接拉、等巡逻走开再拉；
- 连带判断：拉这组时，按导航距离算旁边组是否在仇恨半径内；遭遇会自己派怪的（克里克希尔）按场景数据处理；
- 控制按 TRASH-CC-PULL-DESIGN 流程：脱战时先下控制，再开怪，控制目标周围不放 AoE。

**战后恢复**：吃喝、复活、重新上增益，满足门禁再走下一段。

## 三、分工（指挥链）层

这是核心，也是现在最缺的一层。当前各 boss 策略把分工写死在代码里（「第一个远程」「第一个治疗」），
四骑士里因为加了一名治疗，「第一个治疗」从神圣骑变成了恢复德，事先摆的位置全部对错人。

**分工数据**：一张按阶段组织的表，写进每个 bot 的 AI 值，各 boss 策略从这里读，不再各自数序号。

```
阶段 1: 坦1 → 拉 科尔塔兹 @ 点A；坦2 → 拉 里文戴尔 @ 点B；治疗甲 → 吸 泽里克 @ 点C；
        治疗乙 → 奶副坦 @ 点D；远程 → 点E；击杀顺序：科尔塔兹
阶段 2: 条件「科尔塔兹死亡」→ 坦1 接里文戴尔（副坦 ≥3 层时）……
```

**通用机制模板**（这轮 Naxx 反复出现的模式，做成可配置项，新 boss 主要写配置）：

| 模板 | 参数 | 已出现的 boss |
|---|---|---|
| 按层数换坦 | 减益 id、换坦层数、离开距离与时长 | 格拉斯、四骑士 |
| 吸引/分担 | 目标、站位点、轮换周期或层数 | 四骑士后排 |
| 分边站位 | 分组依据（小队号/职责）、两侧点 | 塔迪乌斯 |
| 躲地面效果 | 效果单位/技能、安全半径、站位约束 | 迈克斯纳、四骑士虚空区域 |
| 开怪前就位 | 角色 → 点 | 四骑士坦克、吸引者、副坦治疗 |
| 远离某单位 | 单位、距离 | 四骑士前排印记（55 码） |

**下达与呈现**：

- 分工由团长生成：AI 团长按模板 + 当前队伍自动分配；真人团长可用聊天指令改（如 `assign <角色|名字> <职责> [标记]`）。
- 宣布：团队频道 / 团队警告，一句一职责。
- 标记：3.3.5 有单位标记，没有地面标记；给怪挂击杀/控制标记，给玩家挂职责标记；位置用临时召唤的可见单位代替（`MovementAction::CreateWp` 已有同类做法）。
- 第一步（小）：按小队号分左右（[BACKLOG](testing/BACKLOG.md) 第 24 条）。

## 四、真人协作

- **真人是坦克**：AI 团长退为参谋——提示下一组怪、挂击杀标记、提示走位，不替真人开怪。
- **真人是输出/治疗**：AI 坦克带队；真人死亡、没蓝、落后超过设定距离时不开下一组，等真人。
- **覆盖与确认**：真人的指令优先于自动分工，bot 在队伍频道回话确认；真人随时 `stay`/`follow` 接管。
- **节奏**：给真人留准备时间（开怪倒数），与 bot 之间不做「瞬间反应」假设。

## 五、验证：raidtest「整本通关」场景

新场景类型，与单 boss 场景并存：

- 入口 = 副本入口；按路线文件依次执行怪组与 boss 段；boss 段复用现有 boss 场景的判据与观察器。
- 记录：总用时、每段用时、灭团次数与位置、卡住次数与位置、`fall_detect` 次数、真人等待时长（有真人时）。
- 中止条件：同一段连续失败 N 次、卡住超时、全灭后无法恢复。
- 结果口径：整本完成率，外加每段的成功率——方便定位是寻路、拉怪还是 boss 出问题。

## 实施阶段

1. **路线格式与工具**：路线文件格式、刷怪聚类初稿、导航校验、GM 录制命令；先做一个结构简单的 5 人本（建议乌特加德城堡）。
2. **全 bot 自动通关**：坦克领队的导航与拉怪循环 + 「整本通关」场景，不含真人；量化完成率与卡点。
3. **分工层**：分工数据、通用机制模板、宣布与标记；先把一个 boss（四骑士或塔迪乌斯）改成读分工验证。
4. **真人加入**：准备检查、等人、按真人职责调整、聊天指令；按 HUMAN-SESSION 实机验证。
5. **扩展**：更多 5 人本、英雄难度，再回到团本。

## 风险

- 导航网格有洞或与碰撞地面不一致（迈克斯纳走穿蛛网即此类）；需要逐段校验与回归指标。
- 载具与交通工具（[VEHICLE-SUPPORT-STUDY](testing/VEHICLE-SUPPORT-STUDY.md)）。
- 脚本事件（护送、连续刷怪通道）：路线里单列特殊段，逐个处理。
- 巡逻时序与连带开怪：拉怪判断本身复杂，先用保守规则（宁可等）。
- 框架与 bot 的边界：导航、拉怪、分工属于 bot 行为，按项目约定放在 playerbots；raidtest 只做路线数据的编排、场景执行与观察（[mod-raidtest 框架边界](04-mod-raidtest-设计.md)）。

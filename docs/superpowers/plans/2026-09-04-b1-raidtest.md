# B1 攻坚底座 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 打通"补全 AI 战斗 → 真实装备 → 实例重置 → Patchwerk 可复现跑到 kill/wipe/timeout 判定"的攻坚链，拿到第一个真实胜负判定。

**Architecture:** 三个聚焦改动落在既有 mod-raidtest 上：B1-1 配置激活既有 bot AI（可能动 mod-playerbots 配置）；B1-2 给 RosterBuilder 加"BIS 表提取装备"路径（只读 mod-playerbots 的 `playerbots_bis_gear` 表）；B1-3 给 AttemptRunner 加跨 attempt 实例重置。全部复用 A 阶段管线与事件流。

**Tech Stack:** C++20（AzerothCore Playerbot fork）、characters/playerbots MySQL 库、worldserver Console 命令、既有 `.raidtest` 命令层。

## Global Constraints

- 零核心修改；mod-raidtest 只改自身文件；mod-playerbots 是否改取决于 B1-1 实测（见 Task 1）。
- 不改伤害倍率/装备属性/boss 机制——装备走既有 BIS 表数据，属"用既有合法数据"。
- `raidtest` logger tag；世界线程非阻塞纪律延续 A 阶段。
- 编译需用户已授权（整个实现期授权仍有效）；`MTHREADS=4` + ccache。
- 配置改动走 `env/dist/etc/modules/playerbots.conf`（gitignored 运行时文件）与模块 `conf/*.conf.dist`（已自动部署）。
- **测试=真实服务器验证**（无单测设施），每任务带服务级验收命令。
- 记住：B1 完成后有 **TODO**（禁用随机 bot 世界游荡）需记录到台账/README。

### Task 2: BIS 装备自动提取（RosterBuilder）——【方案 C：最高档装备】

**方案 C 决策（2026-09-04）：** 用户选择给 bot 配**最高档 BIS 装备（Phase 5/6，ilvl ≤ 284，ICC 25H 档）**跨过 Patchwerk 数值闸。这是合法好装备（不做倍率/属性修改），目的=验证攻坚链"能打掉血"而非停在 99%。装备提取目标从"NAXX 10 人 T7（≤213）"改为最高档。

**Files:**

- Test: 真实服务器 `.raidtest run naxx-patchwerk --attempts 1` + 查角色 inventory

**Interfaces:**

- Consumes: `RosterBlueprint` 的 gear 缺省槽位集合（A 阶段语义：不在 `slot.gear` 即工厂兜底）；`RaidTestConfig`.

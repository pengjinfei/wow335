# B2-1 激活无 master bot 输出循环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 模块侧为每个 raidtest bot 启用 `attack tagged` 策略，让 loot-tagged boss 成为无 master bot 的合法攻击目标，从而激活其自身 DPS 输出循环。

**Architecture:** 在 mod-raidtest 的 bot 登录完成点（`RaidTestOrchestrator::TickLoginAndGroup`）后，遍历 bot 调 `PlayerbotAI::ChangeStrategy("+attack tagged", BOT_STATE_NON_COMBAT)`。这利用 `AttackersValue.cpp:223` 的现成豁免（`HasStrategy("attack tagged", NON_COMBAT)` → canAttack=true），让 boss 对无 master bot 成为合法目标 → "invalid target" 触发器不再踢目标 → class 输出循环（frost/arms/fury）对 current target 正常施法。**施法选择仍由 bot 自身策略决定，不注入脚本化轮换。**

**Tech Stack:** C++20（AzerothCore Playerbot fork）、mod-playerbots `PlayerbotAI::ChangeStrategy` 公共 API、既有 `.raidtest` 命令、`raidtest_events` 表验证。

`src/Bot/RosterLogin.cpp` 实现:
```cpp
bool RosterLogin::ApplyMasterlessCombatStrategy(std::vector<Player*> const& bots)
{
    uint32 applied = 0;
    for (Player* bot : bots)
    {
        if (!bot)
            continue;
        if (PlayerbotAI* botAI = GET_PLAYERBOT_AI(bot))
        {
            botAI->ChangeStrategy("+attack tagged", BOT_STATE_NON_COMBAT);
            ++applied;
        }
    }
    if (applied != bots.size())
    {
        LOG_WARN("raidtest", "RosterLogin::ApplyMasterlessCombatStrategy: applied to {}/{} bot(s)",
            applied, bots.size());
        return false;
    }
    LOG_INFO("raidtest", "RosterLogin: enabled 'attack tagged' on {} bot(s) (masterless combat target fix)",
        applied);
    return true;
}
```
> 头文件需含 `Playerbots.h`（GET_PLAYERBOT_AI）、`BOT_STATE_NON_COMBAT` 枚举、`PlayerbotAI` 前置声明——确认现有 include 覆盖，缺则补。

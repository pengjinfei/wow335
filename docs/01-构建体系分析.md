# 构建体系分析

> 分析对象：
> - 核心服务端：`mod-playerbots/azerothcore-wotlk` 的 **Playerbot 分支**（AzerothCore 的定制 fork）
> - 机器人模块：`mod-playerbots/mod-playerbots` 的 **master 分支**（测试特性在 `test-staging`）
>
> 分析方式：直接审阅上游仓库源码（cmake 脚本、CI 流程、目录结构），非二手资料。

## 1. 总体结构

```
azerothcore-wotlk/                  ← 核心 fork（Playerbot 分支）
├── acore.sh                        ← 运维/构建入口（dashboard 脚本）
├── CMakeLists.txt                  ← cmake 总入口（要求 cmake 3.16~3.22）
├── conf/dist/                      ← cmake 与 shell 的默认配置模板
│   ├── config.cmake                ←   cmake 构建选项默认值 ★
│   ├── config.sh                   ←   数据库等运行时配置默认值
│   └── env.ac / env.docker
├── apps/
│   ├── installer/                  ← acore.sh 的后端（依赖安装、建库、模块管理）
│   │   └── includes/os_configs/osx.sh   ← macOS 依赖清单 ★
│   ├── compiler/                   ← acore.sh compiler 的后端（cmake + make 封装）
│   ├── extractor/extractor.sh      ← 客户端数据提取脚本 ★
│   ├── startup-scripts/            ← 服务器启动脚本
│   └── DatabaseSquash/             ← SQL 历史压缩工具（日常开发不用管）
├── data/sql/                       ← 核心数据库 SQL（见 §5）
├── src/                            ← 核心源码
│   ├── server/apps/worldserver/worldserver.conf.dist   ← 服务器配置模板 ★
│   ├── server/apps/authserver/authserver.conf.dist
│   └── cmake/macros/ConfigureModules.cmake             ← 模块加载机制 ★
├── deps/                           ← 第三方库
└── modules/                        ← 模块目录（mod-playerbots 克隆到这里）
    └── mod-playerbots/
        ├── include.sh              ← 模块 shell 入口（加载 conf）
        ├── conf/playerbots.conf.dist  ← 机器人配置模板 ★
        ├── data/sql/               ← 模块自己的 SQL（含独立数据库）
        └── src/                    ← 模块源码（Ai/ 策略体系都在这里）
```

## 2. 构建链路全景

```
./acore.sh compiler build
      │
      ▼
apps/compiler/compiler.sh（comp_build）
      │  configure: cmake <源码根> → var/build/obj
      │  compile:   make -j N → 产物输出到 env/dist/bin
      ▼
CMakeLists.txt
      ├── include(conf/dist/config.cmake)      ← 构建选项默认值
      ├── include(conf/config.cmake) [若存在]   ← 本地覆盖 ★ 自定义选项放这里
      ├── 扫描 modules/*/CMakeLists.txt 逐个 add_subdirectory
      └── add_subdirectory(modules)
              └── ConfigureModules.cmake
                    └── 扫描 modules/*/src 目录，逐个编译链接 ★
                        （本项目模块不需要根 CMakeLists.txt，
                          有 src/ 目录即被发现——这就是"标准
                          AzerothCore 编不了"的原因之一）
```

**产物位置**：`env/dist/bin/`（worldserver、authserver、mapextractor、
vmap4extractor、vmap4assembler、mmaps_generator 等）。

**构建类型**：默认 `RelWithDebInfo`（有优化、带调试符号，适合本项目）。

## 3. cmake 关键选项（来自 `conf/dist/config.cmake`）

| 选项 | 默认值 | 本项目应设 | 说明 |
|---|---|---|---|
| `SCRIPTS` | `static` | 默认即可 | 副本脚本静态链入（boss AI 依赖它） |
| `MODULES` | `static` | 默认即可 | 模块静态链入 |
| `APPS_BUILD` | `all` | 默认即可 | authserver + worldserver |
| `TOOLS_BUILD` | **`none`** | **`all`** ★ | 地图提取工具，**必须改**，否则无法提取客户端数据 |
| `USE_COREPCH` / `USE_SCRIPTPCH` | `1` | 保持开启 | 预编译头，全量编译提速显著（CI 关掉是为了缓存策略，本地别学） |
| `WITH_DYNAMIC_LINKING` | `0` | 保持 | 动态链接会显著加快增量编译，但官方未验证，初期不碰 |
| `BUILD_TESTING` | `0` | 保持 | 核心单测 |

覆盖方式（**实测：必须用 `conf/config.sh`，不要用 `conf/config.cmake`**）：

`acore.sh compiler` 的 cmake 参数全部来自 `conf/dist/config.sh` 里的
shell 变量（`CTOOLS_BUILD`、`CSCRIPTS`、`CCUSTOMOPTIONS`…），以 `-D` 显式
传入。`conf/config.sh` 加载于其后可覆盖它们。而 `conf/config.cmake` 只在
绕过 dashboard 直接跑 cmake 时生效，且其普通 `set()` 晚于
`ConfigureTools.cmake` 的求值时机——实测设了也不生效。

```bash
# conf/config.sh（本项目实际使用的覆盖）
CTOOLS_BUILD=all          # ★ 默认 none，必须改
AC_CCACHE=true
CCUSTOMOPTIONS=" -DOPENSSL_SSL_LIBRARIES=... "   # 见 §8 Apple Silicon 修复
```

## 4. macOS 平台细节

### 4.1 官方依赖清单（`apps/installer/includes/os_configs/osx.sh`）

```bash
brew install openssl@3 readline boost bash-completion curl unzip \
             mysql ccache expect tmux screen jq
# cmake：CI 里条件安装；另需 Xcode Command Line Tools 提供 clang
```

其中**关键**的是：`boost`、`openssl@3`、`readline`、`mysql`、`ccache`。
（curl/unzip 系统自带，expect/tmux/screen 为运维便利项，可选。）

### 4.2 CI 使用的 cmake 参数（`apps/ci/mac/ci-compile.sh`）

CI 在 macos-14（Apple Silicon）上手动 cmake，显式指定了 Homebrew 路径，
遇到链接问题时照抄：

```bash
export OPENSSL_ROOT_DIR=$(brew --prefix openssl@3)
cmake ../../../ \
  -DSCRIPTS=static \
  -DCMAKE_BUILD_TYPE=Release \
  -DMYSQL_ADD_INCLUDE_PATH=$(brew --prefix mysql)/include/mysql \
  -DMYSQL_LIBRARY=$(brew --prefix mysql)/lib/libmysqlclient.dylib \
  -DREADLINE_INCLUDE_DIR=$(brew --prefix readline)/include \
  -DREADLINE_LIBRARY=$(brew --prefix readline)/lib/libreadline.dylib \
  -DOPENSSL_INCLUDE_DIR="$OPENSSL_ROOT_DIR/include" \
  -DOPENSSL_SSL_LIBRARIES="$OPENSSL_ROOT_DIR/lib/libssl.dylib" \
  -DOPENSSL_CRYPTO_LIBRARIES="$OPENSSL_ROOT_DIR/lib/libcrypto.dylib" \
  -DCMAKE_C_COMPILER_LAUNCHER=ccache \
  -DCMAKE_CXX_COMPILER_LAUNCHER=ccache
```

正常路径下 `./acore.sh compiler build` 会自动处理这些，以上仅作排错备用。

## 5. 数据库机制

### 5.1 四个数据库

| 库名 | 来源 | 内容 |
|---|---|---|
| `acore_auth` | 核心 `data/sql` | 账号、服务器列表 |
| `acore_characters` | 核心 `data/sql` | 角色、公会、拍卖行 |
| `acore_world` | 核心 `data/sql` | 地图、生物、物品、任务 |
| **`acore_playerbots`** | **模块** `data/sql/playerbots/create/create_mysql.sql` | 机器人专用（路线网、权重表、话术库、装备缓存） |

### 5.2 SQL 布局与更新机制

```
data/sql/
├── create/    ← 建库语句
├── base/      ← 全量基线（squash 后的快照）
├── updates/   ← 增量更新 ★ worldserver 启动时自动应用
└── custom/    ← 自定义 SQL（不会被上游覆盖，放自己的改动）★
```

- **DatabaseUpdater**：worldserver/authserver 每次启动时自动检查并应用
  `updates/` 里未应用的 SQL（记录在 `updates` 表里）。模块的同理——
  这就是"更新上游后重启即自动升库"的机制，不需要手工跑 SQL。
- **初始化**：`./acore.sh setup-db` 创建 `acore` 用户和三个核心库并导入
  base；模块库由首次启动自动创建。
- 默认连接参数在 `conf/dist/config.sh`（host=127.0.0.1, user=acore, pass=acore）。

## 6. 配置文件机制

| 文件 | 位置 | 说明 |
|---|---|---|
| `worldserver.conf` | `conf/` | 由 `src/server/apps/worldserver/worldserver.conf.dist` 复制生成；关键项：`DataDir`、`BindIP`、MySQL 连接 |
| `authserver.conf` | `conf/` | 同上 |
| `playerbots.conf` | `conf/` | 由模块 `conf/playerbots.conf.dist` 复制生成；机器人行为总开关、数量上限、反应延迟等 ★ |
| `config.cmake` | `conf/` | cmake 选项本地覆盖（§3） |
| `config.sh` | `conf/` | shell 脚本运行时配置覆盖 |

构建过程会把 dist 配置复制到 `env/dist/etc/`；实际读取路径取决于启动方式
（`acore.sh run-*` 使用 `conf/` 下的文件）。

## 7. 客户端数据与提取

- 编译时 `TOOLS_BUILD=all` 会产出四个工具：
  `mapextractor`（maps）、`vmap4extractor` + `vmap4assembler`（vmaps）、
  `mmaps_generator`（mmaps，寻路，**机器人移动质量的关键**）。
- `apps/extractor/extractor.sh` 封装了完整提取流程，需要指定 3.3.5a
  **enUS** 客户端目录；产出放入 `worldserver.conf` 的 `DataDir`。
- MMAP 全量生成耗时约 1~3 小时（Apple Silicon），可后台挂机。

## 8. 已知风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **comp_configure 硬编码 Intel 路径（实测踩坑）** | `apps/compiler/includes/functions.sh` 对 `darwin*` 硬编码 `/usr/local/opt/...`（Intel Homebrew 前缀），Apple Silicon 上 `/usr/local` 为空，导致 `Could NOT find OpenSSL (missing: Crypto SSL)`；且显式 `-D` 参数覆盖一切自动探测 | 通过环境变量 `CCUSTOMOPTIONS` 传入 `/opt/homebrew` 路径覆盖（它追加在硬编码参数之后）；完整命令见 `docs/02` §4 |
| **CMakeCache 污染（实测踩坑）** | configure 失败后 `var/build/obj/CMakeCache.txt` 会缓存 `*-NOTFOUND` 空值，之后修正环境变量也无效 | 修参数后先 `rm -rf var/build/obj` 再编 |
| **cmake 4.3** vs 项目要求 3.16~3.22 | 本机是 4.3.2，超出项目声明上限；policy 范围内一般可编译，但未被上游验证 | 先直接试；若 configure 报错，`pip3 install cmake==3.31.6` 用其代替（或临时卸载 brew cmake） |
| **MySQL 版本** | 本机实测：brew 的 mysql 9.3.0 因依赖库（protobuf@29）被单独升级而**直接崩溃**（`dyld: Library not loaded libprotobuf-lite.29.4.0.dylib`），且 9.x 非上游主测版本 | **使用 `brew install mysql@8.4`（keg-only）**，编译与运行都用它；cmake 需显式指向其路径（见 §4.2 参数，把 `brew --prefix mysql` 换成 `brew --prefix mysql@8.4`） |
| make 3.81（Apple 老版本） | 对 cmake 生成的 Makefile 无影响 | 无需处理；追求速度可换 Ninja（`-G Ninja`） |
| **enUS DBC 硬要求** | 中文客户端提出来的 DBC 会导致 bot 无技能 | 必须使用英文客户端文件提取 |
| 磁盘占用 | 源码 ~1.5G + 构建 ~8-12G + 客户端数据 ~4.5G + 数据库 ~2G | 预留 ≥20GB 可用空间 |

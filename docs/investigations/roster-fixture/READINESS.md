# 扩展 boss 测试的就绪评估（2026-09-06）

## 结论

可以开始逐个扩展 boss 测试；当前是已通过 Loatheb 回归的十人测试底座，尚不是所有副本均验证过的通用验收平台。

## 已有证据

- 实际角色配置开怪前验收，固定配置快照与指纹可比；不合法配置会阻断开怪。
- 团队注册、人数、显式主坦检查；登录收尾与新建团队顺序已修复。
- run77 两次连续 attempt、run78 同进程复用均零死亡击杀；血 DK 持续输出。
- 现有胜负和事件记录能支持当前单 boss 场景归因。

## 扩展时仍需验证

1. 高装等 fixture-v1 仅作为能力与框架回归基线。另建按副本阶段定义的装备配置，验证机制处理；两种配置分别统计，不能混为策略通过。
2. 25 人配置仍走自动生成路径，未完成与十人固定配置同等的实测验收。
3. 每个新场景核对人数/难度、boss 身份、拉怪点、前置事件与门、重置和胜负判定。多首领、变身、多阶段、载具或特殊完成条件不能默认套用单 boss 死亡判定。
4. 角色检查尚不等于配装最优或完整职业验收；命中/精准/防御阈值、宠物/弹药和部分职业特殊限制仍需补充。
5. 当前重复回归主要覆盖成功击杀路径；新场景要记录 wipe、timeout、脱战和中断后的恢复行为，框架失败与策略失败分开归因。
6. 机制覆盖和批量统计尚需完善。击杀之外记录关键机制是否实际发生、机器人是否正确响应；每场结果关联核心/机器人/框架版本与配置指纹，比较相同基线的多次结果。

## 建议顺序

1. 用现有十人 fixture-v1 复测已注册的 Patchwerk，确认换 boss 后通用流程仍成立。
2. 每次只引入一个新 boss，先核对上游策略与场景前置条件，再做一次冒烟运行及至少三次有效重复尝试；全部结果保留，三次成功仅作初步回归，不等于高置信度稳定性证明。
3. 同步建立副本阶段装备基线，按机制覆盖判断策略是否合格。高装等短时间击杀只能记为该配置下的击杀。
4. 底层策略缺陷按证据单独修复到 mod-playerbots 或核心 fork；框架只编排和观察，不代替机器人处理机制。

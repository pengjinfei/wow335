# 角色配置验收与固定基线（2026-09-06）

## 目的和边界

验证底层机器人策略之前，先证明实际参战角色满足测试配置。角色生成、配置和验收属于 mod-raidtest；不修改核心职业规则、伤害倍率、boss 机制或机器人战斗策略。

本轮固定十人蓝图（Loatheb、Patchwerk 等共用），采用高装等混合配装能力基线，包含 ICC/红玉装备与血 DK 橙斧；不是 NAXX 同阶段装备难度，也不宣称各专精最优配装。25 人蓝图仍使用自动生成路径，不能视为已完成同等固定配置验证。

## 已发现的问题

- run67 后角色 706–715：两名 DK 仅分配 25 点天赋；其他角色 71 点。
- 全员无雕文记录；多个角色无永久附魔/宝石；血 DK 手套为装等 0 的 NPC Equip 40498。
- 初始 DK 地图内分配天赋受等级减 55 的核心规则限制；旧角色从未重新完成分配。
- 工厂先附魔镶嵌，后续蓝图/BIS 换装丢失增强；BIS 查询未限定专精。
- 原来的物品 ID 查找不能区分两把相同武器，附魔可能覆盖同一把。
- 工厂装备与蓝图装备混装可能触发唯一装备冲突，导致戒指/饰品悄悄回退。
- run69：工厂将普通宝石装入血 DK 多彩插槽；新检查在开战前拦截。

## 实现

代码提交：`mod-raidtest/dev 8f06a10`（固定角色配置验收、团队门禁、attempt 行可见性重试与登录清理竞态修复）。

1. 在全员传送到副本后准备角色，使用核心正常天赋预算重新分配指定模板，再补技能与雕文。兼容已有角色与新建角色。
2. BIS 查询按职业、专精和槽位筛选，明确处理 Blood Tank/BloodTank 别名。
3. 完整装备蓝图直接从空装备槽装配，不先放随机工厂装备；不完整蓝图仍可使用工厂/BIS，但同样必须验收。
4. 宝石、附魔按装备槽定位，应用到最终装备。镶嵌后重算插槽奖励及多彩激活状态。
5. 十人蓝图固定装备、宝石、附魔、雕文 ID，并声明必须学会的关键技能。血 DK 修正多彩与激活用宝石、配置石肤石像鬼符文；冰 DK 两把武器分别使用堕落十字军和冰锋符文。
6. 每次 attempt 开怪前验收团队注册、全员同组、人数和显式主坦，并检查角色；失败记录 `aborted / fixture_invalid`，不计为机器人策略 wipe，不调用拉怪。
7. 快照写入 worldserver 工作目录下 `raidtest-rosters/run-N-attempt-M-slot-K.tsv`。快照写入失败也禁止拉怪。

## 验收范围

已检查：等级/职业、71 点已分配天赋和零剩余点、指定关键技能、六个雕文的有效性/类型/重复、必要装备槽、占位物品、物品使用要求、必须附魔的槽位、附魔等级/专业要求、原生插槽填充、普通/多彩类型、宝石使用要求及分类数量上限、多彩条件、实际物品/宝石/附魔/雕文与蓝图一致。

快照包含全部已学技能 ID/激活标志、已分配天赋 ID、雕文、装备 ID/装等/各增强槽 ID、声明专业的实际技能值及上限。`scripts/audit_roster_snapshots.py` 汇总错误并生成配置 SHA-256；忽略 run、GUID 和记录顺序，可比较复用运行和重新建角的角色配置是否相同。

限制：关键技能清单不是全职业技能完备性证明；尚未自动验证全部命中/精准/防御阈值、最优天赋选择、全专业配方、宠物/弹药和所有特殊附魔的职业限制。当前专业沿用 400 等级附近的既有初始化策略，并如实记录；没有宣称全员满专业。固定配置依赖本地 Playerbots 天赋模板，模板变化会体现在实际天赋/技能快照指纹中。

## 后续每个 boss 的流程

固定角色配置和装备档位 → 验收通过并保存快照 → 执行战斗 → 同时查看角色指纹与战斗结果。配置指纹改变时重新建立基线，不能直接把结果变化归因于策略。研究同阶段通关能力时，应另建较低装备档位的版本，保留此高档能力基线。

扩展其他 boss 前，参见 [就绪评估与建议顺序](READINESS.md)。
